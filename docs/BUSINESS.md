## How the plan is built in cfo.ai and comes back

cfo.ai has no REST API and no API key. Data goes in as a CSV upload (a documented data source) and comes back as a file Ari produces for download, or over its MCP server (`https://api.cfo.ai/mcp`, browser OAuth, approved account). The round trip:

1. Sign up at https://cfo.ai/neathacks (then cancel the subscription in Settings → Billing, per the hackathon rules).
2. Run `pnpm notary economics`. It writes `export/cfo-inputs.csv`: one row per real run with model USD by role, tokens, Crustdata credits, unsafe actions and held actions, straight from the bundles. Replay rows (`new_spend` = no) re-serve a recorded run and carry 0 spend, so the sheet never counts a live run twice; `stage` tells recon sweeps (`notarize-recon`) from full notarize runs; a model with no known price leaves `model_usd` empty (unknown, not 0).
3. In cfo.ai, open Connections → Add → Integrations → Upload and choose `export/cfo-inputs.csv` (or attach it to an Ari message and pick "Data source"). Ask Ari to confirm the import finished.
4. Ask Ari to build the plan from that data source (prompt below): pricing per monitored API contract, COGS per contract, cost of incidents prevented, a monthly revenue and COGS projection, cash and runway. Review and adjust the assumptions on the Page.
5. Ask Ari for the plan as a downloadable CSV in Notary's import format (prompt below; header `section,key,label,period,value,unit,detail`). Download the file card. Optionally Share the Page (Share → Create link) and put the link in a `meta,share_url` row.
6. Run `pnpm notary economics --cfo-import <downloaded.csv>`. The plan lands in `packages/web/public/economics.json` (hash-pinned, with the file's sha256 and the import time), on the dashboard's Business page and in this file.

Prompt for step 4 (the assumptions in it are yours to set in cfo.ai; Notary supplies only the per-run costs):

```text
Use the uploaded data source cfo-inputs.csv (one row per Notary run; model_usd, tokens and crustdata_credits are real costs; new_spend=yes rows are billable work; new_spend=no rows are replays with 0 spend; an empty model_usd is an unknown price, not 0).
Build a business plan for Notary, a certification layer that monitors API contracts for AI agents, on a Page named "Notary plan":
1. Three pricing tiers, priced per monitored API contract per month.
2. COGS per monitored contract per month from the live rows (model_usd plus crustdata_credits at our Crustdata credit price).
3. Cost of incidents prevented: unsafe_actions avoided times a cost per incident.
4. A 12-month projection of revenue and COGS, and cash balance with runway in months.
Ask me for any assumption you need (contracts per tier, growth, credit price, cost per incident, starting cash, monthly burn).
```

Prompt for step 5:

```text
Produce a CSV file I can download, nothing else in it, with exactly this header:
section,key,label,period,value,unit,detail
Rows:
- meta rows: key = workspace, page, scenario, exported_at, currency (3-letter); put the text in the value column.
- one tier row per pricing tier: key = short lowercase id, label = tier name, value = price as a plain number, unit = CUR/contract/month, detail = one-line description; plus tier_feature rows (key = tier id, label = feature).
- series rows for the monthly projection: key = revenue, cogs and cash, period = YYYY-MM, value = plain number, unit = the currency.
- figure rows: runway_months, cost_per_incident, cogs_per_contract, gross_margin and any other headline figure; value = plain number, unit as appropriate.
Plain numbers only (no thousands separators or currency signs). Values exactly as in the model, Main scenario.
```

Or read the plan straight from cfo.ai over its MCP server, with no file to download:

1. Run `pnpm notary cfo connect`. It discovers cfo.ai's OAuth server from `https://api.cfo.ai/mcp`, registers Notary as a native client, and opens your browser on cfo.ai's sign-in page; you sign in there (Notary never sees your password). Tokens stay in the gitignored `packages/core/config/cfo-oauth.json`. With several workspaces, pick one (or pass `--org <id>`).
2. In cfo.ai, keep the plan in a table block named "Notary Plan" (or pass `--table` to `sync`, repeatable). Each row name carries its unit in parentheses: dated rows such as `Revenue (USD)`, `COGS (USD)` and `Cash (USD)` become series; timeless rows such as `Runway months (months)` and `Cost per incident (USD)` become figures; `Tier <Name> price (USD/contract/month)` rows become pricing tiers. Rows without a unit, rows split by a Dimension, and cells that are not plain numbers are rejected, never guessed.
3. Run `pnpm notary cfo sync` (or press "Sync from cfo.ai" on the Business tab while `pnpm notary serve` runs). It reads the tables with `inspect_table_blocks` (Main scenario unless `--scenario`), records the workspace and scenario ids, the sync time and the sha256 of the raw MCP payload, and regenerates economics.json and this file. The raw payload stays local in the gitignored `packages/core/config/cfo-last-sync.json`. A response shape Notary does not recognize is rejected with the keys it found, and nothing is written.
4. Notary's per-run costs still go into cfo.ai as the `export/cfo-inputs.csv` upload: cfo.ai's MCP server documents no write of literal data rows (`notary cfo push` explains and exits BLOCKED).
